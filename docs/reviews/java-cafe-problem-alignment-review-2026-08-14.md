## 1. 教材全体の構成とレビュー対象の概要

教材の掲載順は `content/manifest.json`、各章の本文は `content/ch*.json` で管理されている。掲載順とファイル名の番号は一致しない章がある。各JSONは、章情報の下にレッスンを持ち、レッスンには主に次の要素がある。

- 説明文（Markdown、コード、表、SVG図を含む）
- 実行可能なサンプルと期待出力
- 主問題、追加問題、章末問題
- ひな形、公開・非公開テストケース、ヒント、模範解答
- 構文/APIの使用を調べる `sourceChecks`
- クイズ、正答、解説
- 後半では `artifact`、`project`、`runtime-lab`、`preflight`

教材から参照される実習資材は `labs/`、採点・検証は `src/main/java/jq/` と `tools/` にある。今回のレビューでは、本文だけでなく、問題の採点条件、正答、ヒント、実習README、掲載順、前提条件も対象にした。

### F-01 全サンプルが実行時エラーと表示される検証・実行基盤の不具合

- 重要度: **High**
- 状態: **解消（2026-08-15）**
- 分類: その他（検証基盤・学習体験）
- 種別: **明確な不具合**
- 対象ファイル: `src/main/java/jq/runner/ProcessGroupCommand.java`、`tools/verify_solutions.py`
- 対象: 全サンプル実行
- 該当箇所: `ProcessGroupCommand.WRAPPER` の `set -m`、`"$@" &`、`wait`。検証側はsampleのstderrが1文字でもあると失敗扱い。
- 問題点: 非対話bashのjob-control通知 `[1]+ Done "$@"` がstderrへ出るため、正常終了したサンプルを実行時エラーと判定する。既存の厳密検証では確認した全章の全サンプルに同じ誤判定が発生した。
- 初心者に与える影響: 正しいサンプルを実行しても赤いエラーが見える可能性があり、「教材のコードが壊れている」「自分の環境が悪い」と誤解する。教材品質の自動保証も機能しない。
- 修正案: job-control通知を出さずにプロセスグループを作る実装へ変更するか、wrapper由来の通知を子プロセスstderrと分離する。修正後に全360サンプルと全623問題を既存検証で完走させる。
- 修正理由: 独立ランナーでは360/360件が正常であり、教材コードではなく実行ラッパーが原因と切り分けられるため。
- **対応（2026-08-15）:** プロセスグループはfork時に決まるので、`"$@" &` の直後で `set +m` して job-control を切り、`wait` 自身の報告（`Killed: 9` など）も `2>/dev/null` で捨てた。子のstderrはfork時に継承済みなので影響しない。`command not found` のようなbash自身の診断は残る（`/dev/null` へ全部流すと mvn/gradle の起動失敗が見えなくなるため、その形は採らなかった）。bash 3.2（macOS）と 5.2（Linux container）の両方で、正常終了・非ゼロ終了・シグナル死・子プロセスツリーの回収について修正前後を比較した。
- **副産物:** `trimStackTrace` は `at ` 行しか除外しないため、この通知は `RunResult.stderr` を通って**ブラウザの実行画面にも表示されていた**。§8.2の疑問はこれで解消（検証基盤だけの問題ではなかった）。
- **回帰テスト:** `tools/JavaRunnerCheck.java` に `wrapperAddsNothingToStderr()` を追加した。旧wrapperへ戻すと実際に失敗することを確認している。
- **確認:** `./tools/verify-solutions.sh --strict-starters` が完走し、**すべて合格**（318レッスン / 621問 + 任意2 / テストケース3056件（隠し1820件）/ クイズ382問）。実行時エラー・コンパイル失敗・タイムアウト・出力不一致はいずれも0件。

  **断定語（必ず・常に・すべて）を含む選択肢のうち誤答が91.9%**（基準値75%）だった。
  「長い選択肢を選ぶ」「断定を避ける」だけで、Javaを知らなくても正答率が上がる。
- 初心者に与える影響: 理解していないのに正解できるため、クイズが到達の確認として働かない。
  F-04で到達目標をクイズへ紐づけたので、この歪みは目標の達成判定にも影響する。
- **原因は1つだった:** 誤答が「物理サーバー本体」「業務要件そのもの」「一通り確認しました」のような
  投げやりな一言で、**選択肢として成立していなかった**。Javaを知らなくても消せるので、正解だけが
  具体的な技術的記述になり、長さも断定語も正解の側へ偏る。つまり長さと断定語は症状であり、
  病巣は「誤答が具体的でないこと」。
- **対応:** 誤答を**ありえる誤解**へ書き換えた。158問・選択肢439件。`answer`（正解の番号）は
  1問も変えていない。断定語は外すだけでなく、`List.of` の変更や `null` のアンボクシングのように
  **Javaが本当に保証すること**は正解の側で「必ず」と書いた。
- **並べ替えはしていない:** 正解の位置の偏り（118/102/95/76）も見つけたが直していない。
  並べ替えると `progress.json` の `quizChoices`（学習者が選んだ**番号**）の意味が変わり、
  正解した記録が誤答になって復習の苦手度がずれる。選択肢の**文**の書き換えは番号を変えないので安全。
- **見張り:** `tools/check-quiz-fairness.sh`（1秒）を追加した。**長さは文字数ではなく画面上の幅**で
  数える（半角のAPI名を全角と同じ重みで数えないため）。また**見分けられない差は数えない**
  （`void Book(String t) { }` と `Book(int a, int b) { }` の差は半角1つ）。最初は全角8文字ぶんを
  しきい値にしたが、それでは「長いほうを選ぶ」戦略が49.9%通る状態を見逃したため、
  全角2文字ぶんへ締めた。現在は25.6%（偶然の水準25%）。
- **教訓:** 「潰した」と書いた手がかりは、問題が増えれば戻る。**1問ずつのレビューでは戻ったことに
  気づけない**（各問は妥当に見える。偏りは全体を数えて初めて見える）。同じ形の指摘は、
  文章で残すだけでなく数える道具を残すこと。
- **この修正がさらに不具合を生んだ（2026-08-15、同日に解消）。** 誤答を158問書き換えたのに解説を
  28件しか直さなかったため、**37問で解説が「消した誤答」を否定したまま**になっていた
  （例: `42-5#4`「SQLの暗号化や型消去、GCとは関係ありません」——3つとも消した誤答。
  `52-3#1`「Javaの予約語は…READMEの誤字は…」——3つとも消えている）。
  読んだ人には何の話か分からず、**手がかりを潰す前より悪い状態**だった。33問の解説を書き直して解消
  （解説を書き換えたクイズは通算56問、`explanation` の中央値は109→114字）。
  誤答を「ありえる誤解」へ具体化したぶん、解説が否定すべき対象も具体的になり、
  **解説の負担が上がっていた**のを見落としたのが原因。
- **検出のしかた（再現用）:** git の HEAD と現在の `content/*.json` を比べ、消えた誤答にしか
  出てこない語（現在のどの選択肢にも無い語）が `explanation` に残っているものを挙げる。
  常設の検査ツールにはしなかった。語の切り出しに依存するため誤検出が多く
  （`後方互換性` が1語として抽出されるので解説の `互換性` と一致しない、など）、
  最終判断は読むしかない。**選択肢を書き換えたら解説を読み直す**という規則を
  `docs/guide.md`「クイズを足すとき」へ書いた。

## 7. 教材全体に共通する用語や表記の問題

1. **章番号**（2026-08-15に対応済み）
   - ~~「第NN章」が表示番号と内部IDの両方を意味する。最優先で統一する（F-02）。~~
   - 正しくは番号が3つある。`chNN` の**内部番号**、画面に出る**編内番号**、編内番号へ移行する前の**旧通し番号**。
     `content/*.json` は内部番号で書き `localizeChapterReferences` が読み替える。`labs/` は読み替えが効かないので番号を書かない。
     `docs/` は保守者向けに `chNN` を使う。規約は `docs/guide.md`「他の章を参照するとき」、検査は `./tools/check-chapter-refs.sh`。
2. **不変 / 変更不可 / final**
   - `final`参照、unmodifiable collection、immutable object、deep immutabilityを用語として分ける（F-10、F-11）。
3. **辞書順 / 文字コード順 / natural ordering**
   - `String.compareTo`、Comparator、locale-aware collationを区別する（F-12）。
4. **英語語彙の表記**
   - container、image、download、runtimeなど英語をそのまま使う文体と、コンテナ、イメージ、ダウンロード、実行環境という日本語表記が混在する。CLIの固有概念・コマンド名は英語、それ以外は日本語という基準を決める。
5. **コード内の命名**
   - `Scanner sc` と `Scanner s`、説明的な変数名と一文字名が混在する。模範解答では説明的な名前を既定にする（F-15）。
6. **「必ず」「完全に」「止まる」**
   - 条件付きの挙動を断定する語が少数ある。仕様上常に成立する場合だけ使い、それ以外は「起こり得る」「この教材では」にする（F-10、F-11、F-14）。
7. **mini実装と実製品**
   - mini Servlet/CDI/JPA等は学習上有効。各章で「同じ構文」「簡略化した挙動」「実製品でのみ保証されること」を同じラベルで表示すると、章間の粒度が揃う。
