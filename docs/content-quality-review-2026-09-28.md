評価の中心は次の5点。

1. その問題を解くために、その節で学ぶ知識が必要か。
2. 必要なAPIや考え方が、ヒント・解答を開く前に学べるか。
3. サンプルが学習対象の動きを見せ、演習へつながっているか。
4. 解説・問題文・模範解答・採点の要求が一致しているか。
5. 合格したとき、学習目標に到達したと判断できるか。

短い模型や四則演算の演習そのものを問題視しているわけではない。概念導入には有効だが、実APIを使う演習や判断の理由を確かめる問題へ接続する必要がある。また、既に「任意」とされている集計問題を、必須演習の欠陥として数えてはいない。

## 優先度の高い指摘

### 1. P1: スレッドセーフ演習が、スレッドセーフでない解答を合格にする

場所: [22-4の課題とテスト](/Users/ryoto/code/java-learning/content/ch22-servlet.json:425)

課題は「共有フィールド `lastName` を使わず、リクエストごとのローカル変数にする」ことを求める。しかし可視・隠しケースは逐次リクエストの出力確認だけで、当該課題には `sourceChecks` もない。

ひな形のTODOを次のように埋め、共有フィールドを残したまま実行した。

```java
lastName = q.getParameter("name");
if (lastName == null || lastName.isBlank()) lastName = "ゲスト";
s.getWriter().println("こんにちは、" + lastName + "さん");
```

**可視1件・隠し1件の両方が期待出力と一致した。** 共有状態の競合は残っているのに、学習の中心である修正をしなくても合格できる。

改善: 少なくともリクエスト値を保持するフィールドへの代入を検出する。より確実には、2要求の処理を制御して交差させる検証を用意する。ランダムな並行実行を何回か行うだけではなく、誤実装が確実に破綻する条件を作る。後続の実サーバー演習とは別に、この問題単体の合格条件を学習目標へ合わせる。

### 3. P1: 境界値分析を「範囲の内側には誤りがない」と説明している

場所: [72-2の解説](/Users/ryoto/code/java-learning/content/ch72-requirements.json:108)

本文には「境界の値だけを重点的に確かめます」「誤りは範囲の真ん中には潜みません」とある。後者は誤り。内部の特定値にだけ分岐ミスがある場合や、数量と会員種別など条件の組み合わせで失敗する場合は、境界だけでは発見できない。例えば範囲1〜100に対して42だけ誤処理する実装なら、この演習で列挙する `0, 1, 50, 100, 101` を通ってしまう。

境界値は誤りが生じやすい場所を効率よく試す技法であり、内部を無条件に安全とみなす保証ではない。公式教材も境界で誤りが起こりやすいことを理由としており、同値分割・決定表・状態遷移を別の技法として扱う。[ASTQBのISTQB公式教材](https://astqb.org/4-2-black-box-test-techniques/)

改善: 「境界を優先し、同値分割の代表値や業務条件の組み合わせも確認する」へ修正する。境界の数値を列挙する問題に加え、「この要件にはどの分割・組み合わせが必要か」を考えさせる問題にする。

### 4. P1: WBSの100%ルールを、工数の足し算の一致と取り違えている

場所: [71-2の解説・課題](/Users/ryoto/code/java-learning/content/ch71-planning-estimation.json:112)

本文は「子の合計が親より小さいなら、誰も担当していない作業がある」「大きいなら二重に見積もっている」と断定し、演習は工数の合計不一致を「100%ルール違反」と呼ぶ。

しかし、100%ルールの中心は、子が親の成果物・スコープ全体を漏れなく表すこと。工数の一致だけでは、試験や移行が丸ごと抜けたWBSも通る。反対に工数の差は、見積りの更新漏れなどでも起きる。PMI掲載資料でも、親の成果物の全要素を下位の分解が含むという意味で説明されている。[PMI: WBSの基礎](https://www.pmi.org/learning/library/work-breakdown-structure-basics-5919)

改善: 現在のコード課題は「工数集計の整合性検査」として位置付ける。100%ルールは、必要な成果物一覧とWBSを比較し、工数が合っていても成果物が抜けている例で教える。

### 5. P2: 見積りの確度を説明する前提条件が抜けている

場所: [71-3の解説](/Users/ryoto/code/java-learning/content/ch71-planning-estimation.json:185)

「全体のばらつきは二乗和の平方根」「期待値にばらつきを1つ足すと8割強の確度」「同じ確度なら余裕が半分で済む」と一般則のように説明する。

### 9. P2: CDIの節を終えても、Qualifier・Producer・CDIイベントを使う経験が得られない
