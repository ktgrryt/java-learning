# Servlet lab

実Open Libertyへ配備して、Servletの応答とスレッドの扱いを直します。
第22章の「章末演習：ServletとHTTP」が採点に使います。

```
sh run-runtime-lab.sh
```

必要なもの: JDKとMaven。Open Liberty 26.0.0.8 はMavenが取得します（初回は時間がかかります）。
使うFeatureは `servlet-6.1` の1つだけなので、起動は1秒ほどです。

## 何をするか

`src/main/java/cafe/web/OrderServlet.java` を直します。1人で試すと動きますが、
同時に使われると壊れ、応答の作り方にも問題があります。

| 検査 | 実サーバーで起きること |
|---|---|
| `servlet-status` | POSTを受けていないので405、無いIDでも200が返る |
| `servlet-shared-state` | 20本を同時に投げると、19本が**他の要求の名前**を受け取る |
| `servlet-escaping` | 値に混ぜた `<script>` がそのまま本文に出る |
| `servlet-charset` | charsetを指定していないので、応答の日本語が `????` になる |

## 混在は「毎回必ず」起きます

Servletは**1つのインスタンスが複数の要求を同時に処理します**。ひな形は要求ごとの名前を
インスタンスフィールドへ置き、そのあと60ミリ秒待ってから応答を書きます。20本を同時に
投げると待ち時間が重なるので、フィールドは必ず上書きされます。

`sleepQuietly()` は「重い処理」（DB照会や外部API呼び出し）の代わりです。消さないでください。
実務では処理に時間がかかるのが普通で、その間に他の要求が入ってくるのが**通常の状態**です。

## 文字コードは2か所ある

- **応答**（この演習で直す）… `setContentType("text/html; charset=UTF-8")` を**本文を書く前に**呼びます。
  指定しないとサーバー既定（ISO-8859-1）で書き出され、日本語が壊れます。
  検査はServlet自身が書いた「ようこそ」「さん」が届くかを見ます
- **POST本文**（この演習で直す）… `request.setCharacterEncoding("UTF-8")` を
  パラメータを読む前に呼びます。品名の「エスプレッソ」が読み戻せるかで確認します
- **GETのクエリ文字列**（この演習の範囲外）… ここは**コンテナ側の設定**です。
  `setCharacterEncoding`はPOST本文にしか効きません（Servlet仕様）。そのため検査では
  クエリ文字列に日本語を使いません

## 直し方の手がかり

- フィールドに置いてよいのは、**要求に依存しない・不変・スレッドセーフ**なものだけです
  （`OrderStore` はこの条件を満たすのでフィールドに持っています）
- 要求ごとの値はローカル変数へ。ローカル変数はスレッドごとに別なので混ざりません
- 無いものは404、作ったら201と`Location`。本文だけ「見つかりません」にして200を返すと、
  呼び出し側は成功と区別できません
- HTMLへ埋め込む前に `& < > " '` を実体参照へ置き換えます

クラス名と `@WebServlet("/orders/*")` のマッピングは採点の足場が使うので変えないでください。
`OrderStore.java`・`pom.xml`・`server.xml` は参照専用です。
