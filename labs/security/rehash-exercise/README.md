# パスワード保存の移行演習（第46章 48-4の採点対象）

「照合は動くが、保存のしかたが弱い」実装を直す演習です。必要なのはJDKだけです。

編集するのは `exercise/PasswordHasher.java` で、`reference/` が模範解答、`HasherProbe.java` は
固定の検査です。

## 出発点の何が弱いか

出発点はSHA-256を1回だけ計算します。正しいパスワードは一致し、違うパスワードは一致しないので、
テストだけ見ると問題が無いように見えます。足りないのは次の3つです。

| 足りないもの | 何が起きるか |
|---|---|
| 利用者ごとのソルト | 同じパスワードの利用者が同じ保存値になり、まとめて破られる |
| 計算コスト（反復回数） | 1回のハッシュが速すぎて、総当たりが現実的になる |
| 方式と設定の版 | あとで方式を上げるとき、どの保存値が古いのか分からない |

## 直したかどうかの見分け方

| 見るところ | 直っていないとき | 直ったとき |
|---|---|---|
| 保存値の形 | `sha256$<hex>` | `pbkdf2-sha256$210000$<salt>$<導出値>` |
| 同じパスワードを2回保存 | 同じ値 | 毎回変わる |
| 旧形式の保存値 | 照合できる（維持する） | 照合できる |
| `needsRehash` | いつでもfalse | 旧形式と反復回数不足でtrue |

**旧形式を照合できる状態を保つ**のが移行の要点です。全員のパスワードを平文で持っていない以上、
入れ替えられるのはログインに成功した利用者だけです。`needsRehash` がtrueを返した利用者を、
その場で新形式へ保存し直します。

生成物（`out/`）はコミットしません。
