# 領収書のロケール演習

Java実践・開発基盤編『文字列処理とロケール』のレッスン「Locale・NumberFormat・ResourceBundle」が
採点に使います。

**同じ `.class` を3つのロケールで走らせ、出力が変わらないことを確かめる演習です。**
必要なのはJDKだけで、Maven・Docker・ネットワークは要りません。

解説は「引数なしの `toUpperCase()` は既定ロケールに依存します」「同じコードが端末によって
違う言語で出ます」と書いていますが、**手元の1つの環境では確かめられません**。
そこで採点側が `java -Duser.language=… -Duser.country=…` を切り替えて、
3つのロケールで同じ結果になることを見ます。

| ファイル | 役割 |
|---|---|
| `src/cafe/report/Receipt.java` | **編集する。** 領収書の1行を作る（TODO ①②） |
| `src/cafe/report/Main.java` | 参照専用。固定のデータで2行出す |
| `src/cafe/report/Loose.java` | 参照専用。**何も明示しない書き方の見本**（参考表示に使う） |
| `reference/` | 模範解答（画面には出ません） |

## 採点で何が起きるか

| ロケール | ひな形のまま | 直したあと |
|---|---|---|
| `ja_JP` | 通る（自分の環境では正しく見える） | 通る |
| `en_US` | 曜日が `(木)` ではなく **`(Thu)`** | 同じ |
| `tr_TR` | `ISHIDA` が **`İSHİDA`**・桁区切りが **`1.234.567`** | 同じ |

3つのロケールで `2026/01/01(木) ISHIDA 1,234,567円` から始まる同じ2行になれば合格です。
最後に参考として、`Loose`（何も明示しない書き方）を同じ3ロケールで走らせた結果も出します
（採点には含めません）。

## 手元で動かす

```bash
cd labs/text-locale/receipt-exercise
./run-tests.sh              # いまの src/ を検査する（最初は2つ失敗します）
./run-tests.sh reference    # 模範解答を重ねて検査する（すべて通ります）
```
