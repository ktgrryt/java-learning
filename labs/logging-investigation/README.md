# 実務ロギングと障害調査ラボ

注文キャンセルAPIで発生した障害を題材に、混在したログから1件の要求を追い、
安全な調査記録とインシデント報告を作るラボです。

業務アプリ総合演習編『実務ロギングと障害調査』の画面では、SLF4J・Logback・MDCの
使い方を学びます。このラボは外部依存なしで
調査手順へ集中できるよう、JDK標準APIだけで小さなログ解析器を実装します。
実際のアプリで独自ロガーを作る演習ではありません。

## シナリオ

2026-08-11 10:01 UTCごろから、注文キャンセルAPIの500応答が増えました。
`incident/orders.log`には複数要求のログが混ざり、一部の行にはログへ残すべきでない
Authorizationヘッダーと顧客の自由入力が含まれています。

`incident/deployments.txt`には注文サービスの配備履歴があります。配備時刻が近いことは
原因の証明ではありません。事実、仮説、検証方法を分けて扱ってください。

## 作業

1. `LogParser`で区切り形式のログを読み取る
2. `LogSanitizer`で許可項目だけを安定した順に出す
3. `IncidentAnalyzer`で対象requestIdを時系列化し、最初のERRORを探す
4. エラー以前の最新配備を「原因候補」として求める
5. `REPORT.md`を、事実・仮説・検証・緩和策・恒久対策に分けて完成させる

ログ形式は次の通りです。

```text
time|level|service|requestId|event|key=value key=value ...
```

配備履歴は`time|version`です。
