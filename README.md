# ☕ Java Quest

手を動かしながらJavaを学ぶための、ローカルで動く学習アプリです。

1レッスンは **具体例つきの解説 → その場で実行できるサンプル → 練習問題2問** の3段構えです。
書いたコードを提出すると隠しテストを含む全ケースで自動採点され、全部通ると ★ が付きます。

**★ は問題ごと（全268問）に付きます。** 2問目は、解説が教えているのに1問目では手を動かさない
論点をピンポイントで問う **応用問題**です（`5-2` なら、1問目の「合計をためる」に対して
解説にだけ出てくる「掛け算をためる＝階乗」を書きます）。
読む量と書く量がだいたい 1:1 になるよう、「解説で教えたことには必ず対応するアウトプットがある」
状態を目安に作ってあります。クリアした問題は見出し1行に畳まれるので、ページは伸びません。

各章の最後のレッスンには **4択の確認クイズ** が4問付いています。「このコードはコンパイルできるか」
のように、コードを書く形では出題できない知識を試すためのものです（★ の判定には影響しません）。

**どのレッスンにもいつでも飛べます。** 順番のロックはかけていないので、気になる章から始めても、
分からなくなったら前の章に戻っても構いません。どこまで終わったかはサイドバーで一目で分かります。

画面は2つです。**メインメニュー**（起動時）と**レッスン画面**。

**問題は2問が縦に並びます。** エディタ・ヒント・採点結果は問題ごとに独立しているので、
片方を書いている途中でもう片方を提出できます（`⌘+Enter` は**いま書いている問題**を提出します）。
クリアした問題は見出し1行に畳まれ、見出しを押せば開き直せます。

サイドバーの章は既定でたたんであります（▼）。章の見出しを押すと開き（▲）、
いま開いているレッスンの章だけは最初から開いた状態になります。

メニューへ戻るには、左上の **☕ Java Quest** かパンくずの **メニュー** を押します。

## 必要なもの

**JDK 21 以降だけ**です。Maven も npm も要りません（外部ライブラリを一切使っていません）。

```bash
javac -version    # javac 21.x 以上が出れば OK
```

入っていない場合は `brew install openjdk@21` などで入れてください。
JRE ではなく **JDK** が必要です（あなたのコードをコンパイルするため）。

## 起動する

```bash
./run.sh
```

ビルドしてサーバを起動し、ブラウザが自動で開きます（http://localhost:8123）。
終了は `Ctrl+C` です。

| オプション | 意味 |
|---|---|
| `./run.sh --port 9000` | ポートを変える（埋まっていたら+1して探し、実際に使ったポートを表示します） |
| `./run.sh --no-open` | ブラウザを自動で開かない |
| `JQ_JAVA_HOME=/path/to/jdk ./run.sh` | 使うJDKを指定する（複数入れている場合） |

> JDKが複数入っている環境（Homebrew / sdkman / IDE付属など）でも動くように、
> `javac` と `java` は必ず同じJDKから使い、出力は JDK 21 でも動く形にしています。
> JDKを切り替えたときは自動でビルドし直します。

### アイコンをクリックして起動する（macOS）

毎回ターミナルを開くのが面倒なら、Dock から1クリックで起動できるアプリを作れます。

```bash
tools/make-app.sh
```

`~/Applications/Java Quest.app` ができます。**Dock にドラッグ**すれば、以降はアイコンを
クリックするだけでブラウザが開きます（Spotlight で「Java Quest」でも起動できます）。

**止めるときは、Dock アイコンを右クリック →「終了」**（⌘Q でも同じ）。普通のアプリと同じで、
遊んでいる間だけ Dock に残り、終了するとサーバも一緒に止まります。ログアウトや再起動でも
きちんと止まります。

- ターミナルを開いたままにしなくていいです（サーバはアプリの裏で動きます）
- すでに動いているときは二重に起動せず、ブラウザを開くだけです
- ターミナルが無いので、ビルドの失敗やポートの取り合いは**ダイアログ**で知らせます
- ログは `build/server.log` に出ます

ターミナルから起動・停止したいときは、アプリが呼んでいるスクリプトを直接使えます。

```bash
tools/launch.sh            # 起動（バックグラウンド）
tools/launch.sh --stop     # 止める
tools/launch.sh --status   # 動いているか調べる
```

| オプション | 意味 |
|---|---|
| `tools/make-app.sh --dest /Applications` | アプリを置く場所を変える |
| `tools/make-app.sh --name "Java道場"` | アプリの名前を変える |
| `tools/make-app.sh --jdk /path/to/jdk` | アプリが使うJDKを指定する |
| `JQ_PORT=9000 tools/launch.sh` | ポートを変える |

> アプリは `tools/launch.sh` を呼ぶだけの薄い入れ物です（AppleScript の stay-open
> アプレット。こうしておくと「終了」の Apple Event を受け取れるので、右クリック →「終了」で
> サーバまで止められます）。レッスンやコードを直したあとに作り直す必要はありません
> （起動のたびに必要なところだけビルドします）。作り直しが必要なのは
> **このフォルダを別の場所に移したとき**だけです。
>
> Finder から起動されたアプリは Homebrew や sdkman のJDKを見つけられない（`PATH` が
> `/usr/bin:/bin` などに限られる）ので、`tools/make-app.sh` を実行した時点のJDKの場所を
> アプリに書き込んでいます。そのJDKを消したときは、`tools/make-app.sh` で作り直してください。
>
> アプリで起動したまま `./run.sh` すると、ポートが埋まっているので別のポートに立ってしまいます。
> ターミナルから起動し直すときは、先にアプリを終了する（または `tools/launch.sh --stop`）
> ようにしてください。

## 使い方

1. メインメニューで **▶ 続ける** を押す（または章カードを開いて好きなレッスンを選ぶ）
2. 解説を読み、**サンプルを実行**して動きを目で確かめる
3. エディタに自分でコードを書く
4. **▶ 実行してみる** … 採点せずに動かすだけ。気軽に試すためのボタン
5. **✓ 提出して採点** … 全テストケースで採点。全部通ると ★ が付く
6. **問題2**（応用）へ進む。1問目で覚えた形を、少しずらした場面で使ってみる

**▶ 続ける** は、前回いた問題がまだ未クリアならそこへ戻り、クリア済みなら次の問題
（同じレッスンの2問目 → 次のレッスンの1問目、の順）へ進めます。

クリアしたレッスンには **★** が付いて文字がはっきりした色になり、まだのレッスンは
**○** と薄い色になります。★ が付くのは **2問とも** クリアしたときで、途中は
「1/2」と出ます。章ごとに「3/8」のような進み具合とバーが出るので、
メニューでもサイドバーでも、どこまで終わったかがひと目で分かります。

| ショートカット | 動作 |
|---|---|
| `⌘/Ctrl + Enter` | 提出して採点 |
| `⌘/Ctrl + Shift + Enter` | 実行してみる |
| `Tab` / `Shift+Tab` | インデントする / 戻す |

書いたコードは自動保存されるので、ブラウザを閉じても続きから再開できます。

### 詰まったとき

**💡 ヒント** を押すと1つずつ開きます。全部開くと **📖 模範解答** が見られるようになります。
ヒントを使ってもクリア扱いになるので、遠慮なく使ってください。
ただし模範解答は写して終わりにせず、**1行ずつ「なぜそう書くのか」を自分の言葉で説明できるか**
試してみるのがおすすめです。

テストケースは全1448件で、そのうち **943件が隠しテスト**です。
`0`、負の数、境界値（「80点ちょうど」「残高とちょうど同じ額の出金」「`Integer` キャッシュの `127` と `128`」
「1月31日の1か月後」など）が仕込まれているので、たまたま通るコードではクリアできません。

加えて、各章の最後のレッスンに **4択の確認クイズ** が入っています（各章4問、`2-5` だけ6問で全158問）。
出力の一致では試せない次のような論点は、こちらで出題しています。

- 「次のうちコンパイルエラーになるのはどれか」（`byte b = b + 5;` と `b += 5;` の違いなど）
- パッケージを跨いだ `protected` の可視性
- `module-info.java` の `requires` と `exports`、モジュールを置かない場合の扱い
- `Integer` キャッシュの境界、`finally` と `return` の順序、`remove(int)` と `remove(Object)`

> 第7章以降は **Java Silver（SE 17 / 21 相当）の出題範囲** をカバーしています。解説には
> `⚠️ 試験のワナ` として、試験で狙われる間違えやすい形を `✅` / `❌` の対比で載せました
> （`3-5` `4-6` `5-6` `6-5` にも、初心者がそのままハマる形のものを入れてあります）。
>
> クイズの正解と解説は、答え合わせをするまでブラウザへ送られません（判定はサーバ側で行います）。
> 何度でも答え直せます。

> 第1章・第2章と `3-1` は入力を受け取らない問題なので、出力が1通りに決まります。
> そのためこれらには隠しテストがありません（`6-1` も1問目だけ入力なしです）。
> `3-2` 以降は入力が変わるので、隠しテストで「どんな入力でも正しく動くか」が試されます。

## コンテンツを追加・修正する

レッスンは `content/*.json` に入っています。**Javaコードを触る必要はありません。**
編集してブラウザを再読み込みすれば、すぐ反映されます（サーバの再起動も不要です）。

### レッスンを1つ足す

`content/ch04-branch.json` の `lessons` 配列に、次の形で追加します。

```json
{
  "id": "4-7",
  "title": "レッスンのタイトル",
  "explanation": "## 見出し\n\n解説をマークダウンで書く。\n\n```java\nint n = 1;\n```",
  "samples": [
    { "caption": "動かしてみよう", "code": "public class Main { ... }", "stdin": "" }
  ],
  "task": "練習問題の説明（マークダウン）",
  "starterCode": "public class Main {\n    public static void main(String[] args) {\n    }\n}\n",
  "visibleCases": [
    { "label": "5 のとき", "stdin": "5", "expected": "答え" }
  ],
  "hiddenCases": [
    { "label": "0 のとき", "stdin": "0", "expected": "別の答え" }
  ],
  "hints": ["1つ目のヒント", "2つ目のヒント"],
  "solution": "public class Main { ... }",
  "extraTasks": [
    {
      "kind": "applied",
      "task": "2問目の説明（マークダウン）",
      "starterCode": "public class Main { ... }",
      "visibleCases": [{ "label": "…", "stdin": "…", "expected": "…" }],
      "hiddenCases": [{ "label": "…", "stdin": "…", "expected": "…" }],
      "hints": ["…"],
      "solution": "public class Main { ... }"
    }
  ],
  "quiz": [
    {
      "question": "次のうちコンパイルエラーになるのはどれ？（マークダウン可）",
      "choices": ["`a += 1;`", "`a = a + 1;`", "`a++;`", "`++a;`"],
      "answer": 1,
      "explanation": "なぜそうなるのかの解説（マークダウン可）"
    }
  ]
}
```

| キー | 説明 |
|---|---|
| `id` | レッスンID。画面に出るので `4-6` のような形にします。全体で重複しないこと |
| `explanation` | 解説。マークダウン（見出し・箇条書き・表・引用・コードブロック）が使えます |
| `samples` | 解説中の「▶ サンプルを実行」ボタン付きコード。`stdin` は省略可 |
| `starterCode` | エディタの初期状態 |
| `visibleCases` | 提出前から見えるテストケース（問題の仕様として見せるもの） |
| `hiddenCases` | 提出するまで隠れているテストケース。**失敗したケースだけ中身が開示されます** |
| `hints` | 上から順に開示されます。全部開くと `solution` が見られるようになります |
| `solution` | 模範解答 |
| `extraTasks` | **2問目以降**（省略可）。`task` `starterCode` `visibleCases` `hiddenCases` `hints` `solution` を1問目と同じ形で書きます |
| `quiz` | 選択式クイズ（省略可）。`answer` は **0から数えた正解の番号**。`choices` は2つ以上 |

`quiz` の `answer` と `explanation` はブラウザへ渡されません。答え合わせは `/api/quiz` が行うので、
**画面のソースを見ても正解は分かりません**。`answer` が選択肢の範囲外だと起動時にエラーになります。

**判定は「出力の完全一致」です。** ただし各行の行末の空白と、末尾の空行は無視されます
（初心者がつまずきやすく、学習の本題でもないため）。

### 問題を1問足す

レッスン直下（`task` 〜 `solution`）が **1問目**、`extraTasks` の各要素が **2問目以降** です。
`extraTasks` を書かなければ1問だけのレッスンになります。各要素の `kind` は
`practice`（練習問題）/ `drill`（ドリル）/ `applied`（応用）のどれかで、見出しのバッジに出ます
（省略すると `practice`）。

進捗は `レッスンID#連番` で保存されます（`5-2#1` が1問目、`5-2#2` が2問目）。連番は
「レッスン直下 + `extraTasks` の並び順」で決まるので、**`extraTasks` は必ず末尾に足してください**。
途中に挿入すると番号がずれて、すでに付いている ★ が別の問題のものになってしまいます。

問題を足すときの目安は「**解説で教えたことには、必ず対応するアウトプットがある**」状態です。
解説とサンプルが教えている論点を並べ、1問目が実際に手を動かさせている論点を引いて、
残ったものを2問目で問います（残りが無ければ、サンプルを1か所変えるだけの `drill` にします）。
数を増やすこと自体が目的にならないように、この基準に合わない問題は足さない方がよいです。

`starterCode` は **それ単体でコンパイルできる** ようにしてください（学習者が書く部分はコメントで
示します）。「学習者がこれから書くクラス」を参照するひな形は、`verify-solutions.sh` で落ちます。

### 章を1つ足す

1. `content/ch30-xxx.json` を作る（既存のファイルを写すのが早いです）
2. `content/manifest.json` で、所属させたい編の `chapters` にファイル名を足す

画面上の章番号は、各編の `chapters` の並び順で **1から** 自動的に振られます。
既存の進捗を壊さないため、ファイル名とレッスンID（`21-1` など）は保存用IDとしてそのまま使い、
Jakarta EE編の画面では `1-1` のように編内番号へ変換して表示します。
新しい編を作る場合は、`id` `title` `subtitle` `emoji` `chapters` を持つ要素を `parts` に追加します。

### 追加したら検証する

```bash
./tools/verify-solutions.sh
```

全268問について次を確認します。

- `starterCode` がコンパイルできるか（ひな形が壊れていないか）
- `samples` のコードが実行できるか（解説に載せたコードが動かないのは最悪なので）
- `solution` が **全テストケースを通るか**
- ヒントを全部開くと `solution` が取れるようになるか
- 確認クイズの **正解がちょうど1つ** あり、解説が書かれているか（全選択肢を実際に投げて確かめます）

最後に「レッスン134件 / 問題268問（練習問題134問 / ドリル1問 / 応用133問） /
テストケース1448件（うち隠し943件） / 確認クイズ158問」のように集計が出ます。
1448件のテストケースを実際にコンパイル・実行するので、数分かかります。

> 検査は一時サーバ（ポート8765）を自分で立てて、終わったら必ず片付けます。中断（`Ctrl+C`）でも
> 片付きます。このサーバはポートをずらさない設定で起動するので、8765が埋まっていれば
> 「別のサーバに検査が向いてしまった」ではなく、その場でエラーになります。

コンテンツを直したら毎回これを走らせてください。進捗ファイルは書き換えません。

## コードの実行について

提出したコードは、あなたのマシン上で **別のJavaプロセス** として実行されます。
暴走しても学習が止まらないよう、次の制限をかけています。

- 実行時間 **5秒**（超えたら強制終了して「終わらないループかも」と表示）
- メモリ **256MB**
- 出力 **20,000バイト**（超えたら打ち切り）
- サーバの待ち受けは **127.0.0.1 のみ**（同じネットワークの他人からは触れません）

とはいえ「自分の書いたコードが自分のマシンで動く」ことは変わりません。
インターネットで拾ったコードをそのまま提出するのは避けてください。
