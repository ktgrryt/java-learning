# ☕ Java Café

手を動かしながらJavaを学ぶための、ローカルで動く学習アプリです。

レッスンは **具体例つきの解説 → その場で実行できるサンプル → 自動採点される練習問題** の3段構えです。
基礎〜標準APIの章では通常2問、章末演習3問を基本とし、外部システムを扱う章では
アプリ内の問題に加えて `labs/` の実測手順で学びます。
書いたコードを提出すると隠しテストを含む全ケースで自動採点され、全部通ると ★ が付きます。

**★ は問題ごと（全574問）に付きます。** 通常レッスンの2問目は、解説が教えているのに1問目では手を動かさない
論点をピンポイントで問う **応用問題**です（`5-2` なら、1問目の「合計をためる」に対して
解説にだけ出てくる「掛け算をためる＝階乗」を書きます）。
読む量と書く量がだいたい 1:1 になるよう、「解説で教えたことには必ず対応するアウトプットがある」
状態を目安に作ってあります。クリアした問題は見出し1行に畳まれるので、ページは伸びません。

**4択の確認クイズ** は全373問で、**章あたり4〜15問**です。全レッスンにあるわけではありません。
296レッスンのうち**145レッスン**に1〜6問（多くは2問か4問）まとめて置いてあり、残りのレッスンには0問です。
基礎編やWeb編では章の最後の通常レッスンに寄せ、後半の章では各レッスンへ分散させています。
章末演習はほとんどが0問ですが、Java実践・開発基盤編の5章だけは章末演習にも4問ずつ置いています。「このコードはコンパイルできるか」
のように、コードを書く形では出題できない知識を試すためのものです（★ の判定には影響しません）。

**どのレッスンにもいつでも飛べます。** 順番のロックはかけていないので、気になる章から始めても、
分からなくなったら前の章に戻っても構いません。どこまで終わったかはサイドバーで一目で分かります。
各編を選ぶと「学習の前提」が表示されます。初めて学ぶ場合はJava基礎編の第1章から、
後半の編へ進む場合はそこに書かれた編・章を先に終えるのがおすすめです。

画面は3つです。起動時の**学習ホーム**、設備から店舗経営を育てる**カフェ画面**、教材に取り組む**レッスン画面**。
ヘッダーの「📚 学習」「☕ カフェ」で、長いスクロールをせずに2つのメニューを切り替えられます。

### カフェ画面

問題の初回クリアで得たコイン、累計提供数、購入できる設備をまとめて表示します。
学習ホームとは別ページなので、設備をじっくり選びたいときだけヘッダーの「☕ カフェ」から開けます。
最初は設備だけが表示され、★4で「店舗」が解放されます。「アイテム」は、学習と売上の節目まで進んだとき、
または**特別な達成条件を満たしたとき**に初めて登場します。

設備は「販売戦略・抽出力・イベント・クイズ接客・常連サービス・自動営業」の6系統です。
それぞれ12段階あり、現在の設備を上位互換へ順番に買い替え、下位設備の効果は上位設備の性能へ
置き換わります。
設備画面の「売上・ボーナスの意味」を開くと、正解チップや章ボーナスなどが発生するタイミングと
増える報酬を確認できます。

**設備に★の解放条件はありません。** コインが足りれば、どの系統をどこまで伸ばすかは自由です。
歯止めは価格だけで、Rank8以降は1段ごとに**約6.5〜7.5倍**に上がります（効果の伸びは1段あたり
4〜7割なので、上のRankほど1コインあたりの価値は下がる）。だから「1系統を深く掘る」も
「安い段を浅く広く買う」もどちらも成立し、どちらか一方が正解にはなりません。

以前はRankごとに必要★を決めていましたが、それは「今はこのRankしか買えない」という一本道に
なり、どの系統から育てるかという選択そのものを奪っていました。今★が絡むのは設備ではなく、
店構えLv・店舗の出店枠・終盤改装・アイテムの発見条件だけです（どれも一本道なので選択の幅を
狭めません）。

6系統は**それぞれ別のものを増やします**（同じ数値を取り合う系統はありません）。

| 系統 | 増えるもの |
|---|---|
| 販売戦略 | コインが入るすべての場面の単価（問題・章・クイズのチップ・自動売上） |
| 抽出力 | 1回の注文で出す杯数。すべての報酬の土台なので序盤ほど伸びが大きい |
| イベント | 章をすべてクリアしたときのまとめ報酬だけ |
| クイズ接客 | 確認クイズに初めて正解したときのチップだけ |
| 常連サービス | **その日いちばん最初に★を取った1問だけ**。倍率は連続学習日数ぶん積み上がる |
| 自動営業 | 画面を表示している間の自動売上の速度 |

常連サービスは「今日の1杯目」に集中して乗るため、毎日開くほど得になります。連続日数は7日分が
上限（皆勤の日めくりで10日に広がり、途切れても3日分から再開）です。

6つ目の「自動営業」は、アプリ画面を表示している間だけ少しずつ売上を作ります。こちらも
★の条件はなく価格だけが歯止めで、速度は現在の「問題を1問初クリアした売上」の毎分0.5〜5%です。
画面を閉じている間やオフライン中の売上はなく、次の★を取るまでに受け取れる額は最大5問分です。
最上位設備でも上限まで100分かかるため、問題を解くことが報酬の中心である点は変わりません。

設備に加えて、コインを投資して店舗ネットワークを繰り返し拡大できます。出店上限は★4〜502で
段階的に広がります。各店舗の注文数と、完成した章の問題数に応じて育つブランド倍率が設備効果へ
掛かるため、学習に合わせて報酬の桁も少しずつ大きくなります。章制覇ボーナスは、その章の問題数に
比例した通常報酬の25%が基準です。

ブランド倍率は**復習でも育ちます**。復習で正解した問題1問につき1回だけ加算し、初回クリア1問より
小さい重みにしてあるので、新しい問題を解くより復習した方が儲かることはありません。倍率は
これからの報酬に掛かるため、**早く復習した方が得**です。加えて、復習で正解すると自動売上の枠が
戻ります。全574問を終えると★が増えなくなり、それまでは★のたびに戻っていた枠が尽きてしまうため、
完走後は復習が自動営業設備を動かし続ける入口になります。復習でコインを直接もらうことはありません
（クリア済みの問題は何度でも解き直せるので、支払うと無限に稼げてしまう）。

★520以降は、収益倍率に影響しない**終盤改装プロジェクト**へ任意で投資できます。
20問分の★を追加で獲得するたびに次の段階が自動で解放され、現行教材では★520・540・560の
3段階があります。今後章を追加しても、新しいコインの使い道が同じ間隔で増えます。

さらに、設備とは別枠の**スペシャルアイテムが全12種**あります。未発見の枠や総数は表示されず、
新しく見つかったときだけカフェとアイテムタブに通知マークが付きます。
**同じアイテムは1つしか持てません**（購入済みのものは買えません）。

**1枚のカードが持つ効果は1つだけ**です。効果を束ねると、そのカードが何のカードなのか
言えなくなります（「一発で解いた」と「5回以上粘った」のように条件が正反対のものまで
同居していました）。12枠に収まるところまで効果を削り、残したものは全て単独カードにしています。

| アイテム | 効果 | 解放 |
|---|---|---|
| 🪙 ラッキーコイン | 22%の確率で獲得コインが2倍 | ★6 + 累計1万 |
| 🗒️ コンボスタンプ帳 | 5問クリアするたび、その問題のコインが7倍 | 同じ日に異なる15問 |
| 🥄 一発仕上げのタンパー | ヒントなし・1回の提出でクリアした問題が+20% | 1章をヒントなしで制覇 |
| 💧 粘りのドリッパー | 5回以上提出してクリアした問題が2倍 | 1問へ累計10回提出 |
| 📅 皆勤の日めくり | 「今日の1杯目」の連続日数の上限が7日→10日 | 7日連続で学習 |
| 🚚 移動販売トラック | 注文の集客が2店舗ぶん増える | 店舗を5店まで広げる |
| 📣 ひらめきメガホン | 確認クイズの初回正解チップが20倍 | クイズ20問連続正解 |
| 🎂 祝福のホールケーキ | 章の初制覇コインが4.5倍 | 1章を同じ日に制覇 |
| 🗺️ フランチャイズ地図 | 新店舗の出店費が25%OFF | ★170 + 累計5000万 |
| 🧰 マイスター工具箱 | 設備アップグレードが20%OFF | ★240 + 累計5億 |
| 📖 **復習ノート** | 復習が育てるブランド倍率の成長が4倍 | **復習で異なる200問**（重い） |
| 🏆 **生涯学習トロフィー** | すべての学習報酬が13%増加 | **無傷で25問連続クリア**（重い） |

下2つが**取得の重いアイテム**です。全574問の3分の1以上を復習するか、ヒントなし・1回の提出で
25問続けないと姿を見せません。残り10個は学習を進めれば自然に手に入ります。

解放のされ方は2通りで、9種は**特別な達成条件**（★の数ではなく学ぶ過程そのもの）、3種は
**学習の節目**（★の数と累計コイン）です。手に入れたカードには達成条件が表示されます。
いちど達成すれば、あとで連続が途切れても解放は取り消されません。

初回の条件を逃しても取り返せます。同じ日に異なる15問を復習する、章の全問へもう一度正解する、
確認クイズの異なる20問へ連続正解する、復習で異なる25問に連続正解する、といった復習でも
対応するアイテムが解放されます。同じ1問・クイズの連打では数は増えず、復習では★や
通常の学習報酬も再付与しません。
また、カフェを育てず全問を終えた場合は、★条件を満たしている節目型アイテムの未所持分を完走記念品として
自動で受け取ります。新しい章や節目型アイテムが追加された場合も、その時点の全章を終えれば再評価されます。

#### 店構えの絵

画面の左に出る店構えは、`web/cafe-scene.js` が1枚のSVGとして描いています（外部ライブラリなし）。
店舗ランク1〜12で建物の骨格と時代の配色が変わり、購入した設備がそのまま絵の中の要素として増えます。
ランク1は屋台、ランク7で建物が完成し、ランク8以降はその建物のまま夜へ向かって配色と演出が変わります。
朝の光から星空まで、進み具合が一目で分かるようにしてあります。

**レッスンの問題が縦に並びます。** エディタ・ヒント・採点結果は問題ごとに独立しているので、

クリアした問題は見出し1行に畳まれ、見出しを押せば開き直せます。

サイドバーの章は既定でたたんであります（▼）。章の見出しを押すと開き（▲）、
いま開いているレッスンの章だけは最初から開いた状態になります。

学習ホームへ戻るには、左上の **☕ Java Café** かパンくずの **メニュー** を押します。

## 必要なもの

学習アプリ本体は **JDK 21以降だけ**で動きます。Mavenもnpmも不要です。
`labs/testing-maven` と `labs/frameworks` は、実際の依存管理、JUnit、各runtimeを学ぶため
Maven 3.9以降を別途使います。

```bash
javac -version    # javac 21.x 以上が出れば OK
```

入っていない場合は `brew install openjdk@21` などで入れてください。
JRE ではなく **JDK** が必要です（あなたのコードをコンパイルするため）。

## 起動する

```bash
./run.sh
```

ビルドしてサーバを起動し、ブラウザが自動で開きます（http://localhost:8123）。
終了は `Ctrl+C` です。

| オプション | 意味 |
|---|---|
| `./run.sh --port 9000` | ポートを変える（埋まっていたら+1して探し、実際に使ったポートを表示します） |
| `./run.sh --no-open` | ブラウザを自動で開かない |
| `JQ_JAVA_HOME=/path/to/jdk ./run.sh` | 使うJDKを指定する（複数入れている場合） |

> JDKが複数入っている環境（Homebrew / sdkman / IDE付属など）でも動くように、
> `javac` と `java` は必ず同じJDKから使い、出力は JDK 21 でも動く形にしています。
> JDKを切り替えたときは自動でビルドし直します。

### アイコンをクリックして起動する（macOS）

毎回ターミナルを開くのが面倒なら、Dock から1クリックで起動できるアプリを作れます。

```bash
tools/make-app.sh
```

`~/Applications/Java Café.app` ができます。**Dock にドラッグ**すれば、以降はアイコンを
クリックするだけでブラウザが開きます（Spotlight で「Java Café」でも起動できます）。

**止めるときは、Dock アイコンを右クリック →「終了」**（⌘Q でも同じ）。普通のアプリと同じで、
遊んでいる間だけ Dock に残り、終了するとサーバも一緒に止まります。ログアウトや再起動でも
きちんと止まります。

- ターミナルを開いたままにしなくていいです（サーバはアプリの裏で動きます）
- すでに動いているときは二重に起動せず、ブラウザを開くだけです
- ターミナルが無いので、ビルドの失敗やポートの取り合いは**ダイアログ**で知らせます
- ログは `build/server.log` に出ます

ターミナルから起動・停止したいときは、アプリが呼んでいるスクリプトを直接使えます。

```bash
tools/launch.sh            # 起動（バックグラウンド）
tools/launch.sh --stop     # 止める
tools/launch.sh --status   # 動いているか調べる
```

| オプション | 意味 |
|---|---|
| `tools/make-app.sh --dest /Applications` | アプリを置く場所を変える |
| `tools/make-app.sh --name "Java道場"` | アプリの名前を変える |
| `tools/make-app.sh --jdk /path/to/jdk` | アプリが使うJDKを指定する |
| `JQ_PORT=9000 tools/launch.sh` | ポートを変える |

> アプリは `tools/launch.sh` を呼ぶだけの薄い入れ物です（AppleScript の stay-open
> アプレット。こうしておくと「終了」の Apple Event を受け取れるので、右クリック →「終了」で
> サーバまで止められます）。レッスンやコードを直したあとに作り直す必要はありません
> （起動のたびに必要なところだけビルドします）。作り直しが必要なのは
> **このフォルダを別の場所に移したとき**だけです。
>
> Finder から起動されたアプリは Homebrew や sdkman のJDKを見つけられない（`PATH` が
> `/usr/bin:/bin` などに限られる）ので、`tools/make-app.sh` を実行した時点のJDKの場所を
> アプリに書き込んでいます。そのJDKを消したときは、`tools/make-app.sh` で作り直してください。
>
> アプリで起動したまま `./run.sh` すると、ポートが埋まっているので別のポートに立ってしまいます。
> ターミナルから起動し直すときは、先にアプリを終了する（または `tools/launch.sh --stop`）
> ようにしてください。

## 使い方

1. 学習ホームで **▶ 続ける** を押す（または章カードを開いて好きなレッスンを選ぶ）
2. 解説を読み、**サンプルを実行**して動きを目で確かめる
3. エディタに自分でコードを書く
4. **▶ 実行して採点** … 実行するとそのまま全テストケースで採点します。全部通ると ★ が付き、
   通らなければどのケースで落ちたかが出ます。**実行と回答は同じ操作**です
5. 次の問題へ進む。章末演習では、続けて「組み合わせ」「実践」に挑戦する
6. 一度クリアした問題は **🔁 復習する** から解き直せる（→ [復習モード](#復習モード)）

ボタンを「試す」と「提出」に分けていないのは、**考えながら書ける**ようにするためです。
分かれていると「まだ提出できる形になっていないから試すだけ」と身構えてしまいます。
1つにすると、書けたところまでを気軽に走らせて、落ちたケースを見ながら直していけます。
そのぶん失敗の回数は増えるので、復習の苦手度は1回あたり0.25点しか上がりません
（→ [復習モード](#復習モード)）。

**▶ 続ける** は、前回いた問題がまだ未クリアならそこへ戻り、クリア済みなら次の問題
（同じレッスンの2問目 → 次のレッスンの1問目、の順）へ進めます。

クリアしたレッスンには **★** が付いて文字がはっきりした色になり、まだのレッスンは
**○** と薄い色になります。★ が付くのは **そのレッスンの全問** をクリアしたときで、途中は
「学習中」と出ます。メニューでもサイドバーでも、総量を意識せず現在地だけ確認できます。

| ショートカット | 動作 |
|---|---|
| `⌘/Ctrl + Enter` | 実行して採点 |
| `Tab` | 選んでいる補完候補を入れる（候補が出ていなければインデント） |
| `Shift + Tab` | インデントを戻す |
| `↑` `↓` | 補完候補を選ぶ |
| `Esc` | 補完候補を閉じる |
| `Ctrl + Space` | 補完候補を自分から出す |

書いたコードは自動保存されるので、ブラウザを閉じても続きから再開できます。

### 復習モード

学習ホームの **▶ 続ける** の下にある **🔁 復習する** から、一度クリアした問題を解き直せます。

```
┌──────────────────────────────────────────────┐
│   ╭───╮   🔁 復習する                        │
│   │⏰ 3│   解き直して定着させる               │
│   ╰───╯   忘却曲線でそろそろ確認したい問題から │
│           ┌────────┬────────┬──────────────┐ │
│           │🔁すべて│🔥苦手  │🔖ブックマーク│ │
│           │  7問   │  3問   │     2問      │ │
│           └────────┴────────┴──────────────┘ │
│           今回の出題    [ ▶ 復習を始める ]    │
│           ⏰ 期限切れ 3問 ＋ 早めの復習 7問   │
├──────────────────────────────────────────────┤
│  1問だけ選んで復習する                       │
│  2-1 変数を作って使う ⏰19日過ぎ 🔥苦手 [▮] │
│  5-2 while文で繰り返す ⏰7日過ぎ もう一度[▯] │
│  1-1 はじめての出力     あと5日   安定  [▯] │
└──────────────────────────────────────────────┘
```

出題は**忘却曲線の期限順**です。問題ごとに「次に確認したい日」を持ち、期限を過ぎたものから
順に出します。抽選ではないので、そろそろ危ない問題が後回しになりません。

- **一度正解するとしばらく出てきません。** 正解するたびに間隔が伸びます
  （**1 → 3 → 7 → 14 → 30 → 60 → 120日**）。初クリアの翌日が最初の期限です。
- **同じ日に失敗してから通した問題は、間隔を1段戻します。** 危なかったので早めにまた出ます。
- **失敗しただけでは期限は動きません。** 通せていないのだから、また出てくるのが正しい挙動です。
  そのまま閉じても期限切れとして残り、次の復習で出てきます。
- 期限日そのものは保存せず、「最後に復習した日 + レベルの間隔」で毎回引き直します。
  だから間隔（`REVIEW_INTERVAL_DAYS`）を調整すると、過去の記録にもそのまま効きます。

苦手度は**同じ期限のときにどちらを先に出すか**を決めます（出題そのものは期限が決めます）。

- 実行が通らないと苦手度が **0.25点** 上がります（上限8点）。実行＝採点なので書いている
  途中の失敗も全部届くため、1回あたりを従来の1/4にしてあります。4回失敗して1点ぶんです。
- **復習で正解すると1点まとめて下がります。**
  一覧には `🔥 よく間違えた` / `🔥 苦手` / `もう一度` / `安定` と出ます。
- **ブックマーク**は、しおりのボタン（塗り＝付いている / 線だけ＝付いていない）で
  問題の見出しからも復習の一覧からも付け外しできます。期限が同じときに先に出るようになり、
  「ブックマーク」で絞り込めば付けた問題だけを復習できます。
- 1回の復習は最大10問です。**期限が来たものを先に出し、10問に足りなければ期限が近い順で
  補います**（「早めの復習」と表示）。0問の画面を見せると復習の習慣が途切れるので、
  いつでも始められる形にしています。終わると正解数が出ます。

復習では**ひな形から解き直します**。前に書いた解答は消えません（復習中は保存しないので、
通常のレッスン画面を開けば以前のコードがそのまま残っています）。ヒントと模範解答は
クリア済みなのでいつでも見られます。

★は増えないので、コインも増えません。ただし**達成型アイテムの解放条件は復習でも進みます**
（「復習で異なる10問に連続正解」など。→ [カフェ画面](#カフェ画面)）。

### コード補完

クラス名・メソッド名・変数名・パッケージ名を途中まで打つと、候補が出ます。
`sc.` のように `.` を打った直後は、その変数の型に合わせたメソッドだけが並びます
（`List<String>` なら `list.get(0).` で String のメソッドが出る、というところまで追います）。
自分で書いたクラス・メソッド・変数も候補になります。

候補は `Tab` で入ります。メソッドなら `()` まで付き、引数があるものはかっこの中に
カーソルが入ります。**候補が出ていないときの `Tab` は、今までどおりインデント**です。

文字列やコメントの中では出ません。日本語入力の変換中も邪魔をしません。

### 詰まったとき

**💡 ヒント** を押すと1つずつ開きます。全部開くと **📖 模範解答** が見られるようになります。
ヒントを使ってもクリア扱いになるので、遠慮なく使ってください。
ただし模範解答は写して終わりにせず、**1行ずつ「なぜそう書くのか」を自分の言葉で説明できるか**
試してみるのがおすすめです。

**画面のソースを見ても正解は分かりません**。`answer` が選択肢の範囲外だと起動時にエラーになります。

クイズを足すときは、**Javaを知らなくても解けてしまう手がかりを作らない**ようにします。過去に3つ潰しました。

| 手がかり | 対策 | 現在 |
|---|---|---|
| 正解の位置が偏る | 4か所へ均す | 80 / 92 / 89 / 76 |
| 正解だけが長い（説明文になっている） | 理由は `explanation` へ移し、誤答を具体化する | 差は最大9字 |
| 「必ず・常に・すべて」が誤答にだけ出る | 水増しの断定語を外し、Javaが本当に保証することは正解にも断定語で書く | 的中率73.3%（4択の基準値75%） |

`explanation` は **誤答が誤りである理由まで**書きます。正解の理由しか書いていないと、間違えた学習者は
自分の考えのどこが違ったのか分からないままになります（全373問の中央値109字）。

通常の判定は「出力の完全一致」です。加えて`sourceChecks`がある問題では、`switch`や
`@Transactional`など問題で指定した書き方も確認します。これは完全なJava構文解析ではなく、
学習対象を実際に一度は書いてもらうための補助検査です。出力比較では各行の行末の空白と、
末尾の空行を無視します（初心者がつまずきやすく、学習の本題でもないため）。

`sourceChecks` を足すときは、次の2つを満たすようにします。

- **問題文が明示している構文だけを縛る。** 問題文が別の書き方を許しているなら検査を入れません
  （正しい別解を弾くと、学習者は理由の分からないまま落ちます）。書き方を縛りたいなら、
  先に問題文へ「〜で書いてください」と書きます。
- **模範解答は必ず通り、ひな形のままでは通らない。** ひな形が既にその構文を含んでいる場合、
  その検査は何も確かめていないので入れません。前者は `verify-solutions.sh` が確認します。

テキストブロックや文字列・コメントの中身は検査の前に空白へ置き換えられるので、
`"""` やリテラルの中身は `pattern` で数えられません（外側の `.formatted(...)` などを見ます）。
「`case LOW_STOCK` を書く」のような**構造**は検査できますが、「`"残りわずか"` と表示する」のような
**文言**は検査できません。文言はテストケースの出力比較で確認します。

現在 `sourceChecks` は **661件**あり、295問で使っています。
出力比較だけで十分な問題には付けず、学習対象の構文を実際に書いたか確かめられる場合だけ使います。
正規表現が模範解答で本当に成立するかは `tools/CheckCount.java` で確かめられます。これは採点と同じ
`jq.judge.SourceChecker.codeOnly` と同じ正規表現フラグを使ってヒット数を数えるだけの道具なので、
数分かかる `verify-solutions.sh` を待たずに、書いた検査の当たり外れが分かります。

**別解を弾いていないか**は、模範解答が通ることとは別に確かめる必要があります。「`Arrays.sort` を必須にすると
`Collections.sort` で書いた正解が落ちる」ような縛りは、学習者から見ると理由の分からない不合格になります。
上の1つ目の規則がそれで、迷ったら検査を足さずに出力比較へ任せます。

### ファイルを作る問題を書くとき

提出1回につき **コンパイルは1回だけ** で、そのあとテストケースの数だけ実行します。
作業ディレクトリはケース間で共有されるので、**あるケースが作ったファイルは次のケースにも残ります**。

そのため、ファイルを扱う問題は必ず「まず書く（`writeString` / `write` は上書き）」か
「まず消す（`deleteIfExists`）」から始める形にしてください。`APPEND` だけで組み立てると、
ケースの順番や回数で結果が変わり、採点が安定しません。「まだファイルが無いこと」を
前提にした出力（最初の `exists` が `false` など）も同じ理由で避けます。

### 図を入れる

解説の中に図を置けます。` ```svg ` のブロックにSVGを書くと、キャプション付きの図として出ます
（開始行の `svg` のうしろに書いた文字がキャプションになり、そこではマークダウンも使えます）。

````
```svg 変数が持っているのは「本体がどこにあるか」だけ
<svg viewBox="0 0 720 120">
  <rect class="fig-box" x="20" y="30" width="150" height="40" rx="6"/>
  <text class="fig-t fig-code" x="34" y="50">Point a</text>
  <line class="fig-line" x1="176" y1="50" x2="300" y2="50" marker-end="arrow"/>
</svg>
```
````

決まりは3つだけです。

1. **色は書かない。** クラスで当てます（`fill="#fff"` のような指定は落とされます）。ライト／ダークの切り替えに図も自動で追従させるためです。
2. **`id` は書かない。** 同じページに図が何枚も並ぶので、矢印に必要な `id` は変換側が図ごとに振ります。
3. **矢印は `marker-end="arrow"`** と書きます。`arrow` / `arrow-accent` / `arrow-ok` / `arrow-ng` の4種で、`marker-start` も同じです。

使えるクラスはこれだけです（`web/style.css` の「解説中の図」の節）。

| 用途 | クラス |
|---|---|
| 箱 | `fig-box` `fig-box-plain` `fig-box-accent` `fig-box-ok` `fig-box-ng` `fig-box-dim` |
| 囲い・塗り | `fig-region`（破線の枠） `fig-fill` `fig-fill-accent` `fig-fill-ok` `fig-fill-ng` `fig-fill-dim` |
| 線 | `fig-line` `fig-line-accent` `fig-line-ok` `fig-line-ng` `fig-line-soft` `fig-dashed` |
| 文字 | `fig-t`（基本） `fig-t-dim` `fig-t-faint` `fig-t-ok` `fig-t-ng` `fig-t-accent` `fig-title` `fig-small` `fig-mono` `fig-code` |

- `viewBox` は必須です。**幅は700〜760** で描くと本文の幅に合います（`.lesson-view` が860px）。
- 表示寸法は `viewBox` から決まり、**縮小しません**。狭い画面では表と同じく図の中だけが横スクロールします。
- `fig-t` に `dominant-baseline: middle` が入っているので、`y` は文字の **中心** で指定します。
- 使えるのは `g rect circle ellipse line polyline polygon path text tspan title desc` と座標・書式の属性だけです。
  それ以外（`<script>` `<image>` `<a>` `onclick=` など）は取り除かれます。
- **書き間違えると図にならず、コードブロックとして表示されます**（黙って消えないので、画面を見れば気づけます）。
- ` ```svg ` は**行頭から**始めてください。段落の途中に差し込むと、フェンスとして認識されずに崩れます。

### 問題を1問足す

レッスン直下（`task` 〜 `solution`）が **1問目**、`extraTasks` の各要素が **2問目以降** です。
`extraTasks` を書かなければ1問だけのレッスンになります。各要素の `kind` は
`practice`（練習問題）/ `drill`（ドリル）/ `applied`（応用）のどれかで、見出しのバッジに出ます
（省略すると `practice`）。

進捗は `レッスンID#連番` で保存されます（`5-2#1` が1問目、`5-2#2` が2問目）。連番は
「レッスン直下 + `extraTasks` の並び順」で決まるので、**`extraTasks` は必ず末尾に足してください**。
途中に挿入すると番号がずれて、すでに付いている ★ が別の問題のものになってしまいます。

問題を足すときの目安は「**解説で教えたことには、必ず対応するアウトプットがある**」状態です。
解説とサンプルが教えている論点を並べ、1問目が実際に手を動かさせている論点を引いて、
残ったものを2問目で問います（残りが無ければ、サンプルを1か所変えるだけの `drill` にします）。
数を増やすこと自体が目的にならないように、この基準に合わない問題は足さない方がよいです。

`starterCode` は **それ単体でコンパイルできる** ようにしてください（学習者が書く部分はコメントで
示します）。「学習者がこれから書くクラス」を参照するひな形は、`verify-solutions.sh` で落ちます。

### 追加したらコードを整形する

`samples` `starterCode` `solution` は「読んで覚える見本」なので、1行に詰め込まれた状態で
残しません。JSONに書くときは1行で書いてしまってもよく、あとから次で整えられます。

```bash
./tools/format-content-code.sh            # 詰め込まれているものだけ整形して書き戻す
./tools/format-content-code.sh --check    # 書き戻さず、対象件数だけ見る
```

整形は画面の表示にも使っている `jq.format.JavaSnippetFormatter` に任せます。改行とインデント
だけでなく、演算子・カンマ・キーワードのまわりの空白もそろえます（`int n=s.nextInt();` →
`int n = s.nextInt();`）。すでに整っているコードには触りません。

書き戻す前に全件で2つの条件を確かめ、1件でも崩れていたら何も書き戻しません。

- **トークン列が整形前後で一致する**（空白と改行しか変えていない）
- **もう一度整形しても変わらない**（冪等）

走らせたあとは、次の `verify-solutions.sh` を必ず通してください。

### 追加したら検証する

```bash
./tools/verify-solutions.sh
```

全574問について次を確認します。

- `starterCode` がコンパイルできるか（ひな形が壊れていないか）
- `samples` のコードが実行でき、`expected` がある場合は出力も一致するか
- `solution` が **全テストケースを通るか**
- `solution` が `sourceChecks` の指定構文を満たすか
- ヒントを全部開くと `solution` が取れるようになるか
- 確認クイズの **正解がちょうど1つ** あり、解説が書かれているか（全選択肢を実際に投げて確かめます）

最後に「レッスン296件 / 問題574問（練習問題271問 / ドリル63問 / 応用240問） /
テストケース2838件（うち隠し1797件） / 確認クイズ373問」のように集計が出ます。
2838件のテストケースを実際にコンパイル・実行するので、数分かかります。

カフェと復習に4つの回帰チェックがあります。

```bash
./tools/simulate-cafe.sh          # 全574問を通したときの経済（投資率・買い切れるか）を試算
./tools/check-achievements.sh     # 初回達成・復習での再達成・完走時救済を含むアイテム条件を検査
./tools/check-review-economy.sh   # 今日の1杯目と、復習が渡す倍率・枠の上限を検査
./tools/check-review-schedule.sh  # 忘却曲線の期限と、苦手度の目盛り（0.25点刻み）を検査
```

`check-review-schedule.sh` は復習の出題を決める土台を検査します ―「初クリアの翌日が最初の
期限」「正解で 1→3→7→14→30→60→120日 と伸びる」「同じ日に失敗してから通したら1段戻る」
「失敗だけでは期限が動かない（期限切れのまま残る）」「旧ファイルの苦手度を4倍して読み替える」。

`simulate-cafe.sh` は本番と同じ `ProgressStore` で全問クリアを再現し、設備・自動営業・アイテム・
店舗・終盤改装を安い順に買い切れること、自動売上が毎分学習報酬の5%、
次の★まで5問分の上限を超えないことを確かめます。
**問題数を増やしたときは必ず走らせてください**（1問あたりの報酬が積み上がるので、
教材を増やすとそれだけで投資率が下がります）。

試算は2シナリオを回します。効果が「学習の仕方」に依存する要素（今日の1杯目、復習が育てる
ブランド倍率）は、片方だけでは0と読まれてしまうためです。

| シナリオ | 内容 | 判定 |
|---|---|---|
| plain | 同じ日に一気に完走し、復習しない | 投資率 **25〜45%**。バランスの下限 |
| reviewer | 7日連続で通い、全問を復習・全クイズを解き直す | 投資率 45%以下。復習1問が初回クリア(170bp)を超えないこと |

連続日数は `streak()` が `LocalDate.now()` を見るため直接は作れませんが、直近7日の
`clearDates` だけを書いた進捗ファイルを先に置いて読ませれば作れます。

さらに**買う順番**を4通り試します。設備の★解放条件を外して歯止めが価格だけになったので、
「これを買うのが正解」という一手があると、選択の自由が見かけ倒しになるためです。
安い順（基準）・高い順・抽出力優先・販売戦略優先で完走し、生涯売上が基準の
**0.2〜1.5倍**に収まることを確かめます。現在はどの順番でも 1.00 倍で、順番の差は
ほぼ出ません（上のRankほど1コインあたりの価値が下がるので、深掘りと浅く広くが釣り合う）。

`check-review-economy.sh` は上限そのものを試します ―「今日の1杯目は1日1回」「復習の倍率は
1問1回」「復習で戻る枠は既定の5問分より広がらない」「設備費の割引は合計40%で止まる」。
ここが崩れると無限に稼げてしまうので、復習まわりを触ったら必ず走らせてください。

## コードの実行について

提出したコードは、あなたのマシン上で **別のJavaプロセス** として実行されます。
暴走しても学習が止まらないよう、次の制限をかけています。

- 実行時間 **5秒**（超えたら強制終了して「終わらないループかも」と表示）。
  コードが別のコマンドを起動していた場合も、**子孫プロセスまでまとめて止めます**
- メモリ **256MB**
- 出力 **20,000バイト**（超えたら打ち切り）
- コードの長さ **60,000文字**（実行・保存とも）
- 同時に走らせる実行は **4件まで**。実行は1件で最大5秒×ケース数かかるため、
  数を絞らないと画面の表示まで待たされます。溢れたぶんは「混み合っています」と返します
- サーバの待ち受けは **127.0.0.1 のみ**（同じネットワークの他人からは触れません）
- 操作を受け付けるのは **このマシンのブラウザで開いたこの画面から** のみ。
  他のサイトのページから `http://localhost:8123/api/run` を叩いてコードを実行させる、
  という手（CSRF・DNSリバインディング）を `Host` と `Origin`、それに `Sec-Fetch-Site` の
  確認で塞いでいます。待ち受けを 127.0.0.1 に絞るだけでは、リクエストがあなたの
  ブラウザから出ていくこの経路は防げないためです（`src/main/java/jq/web/RequestGuard.java`）
- 外部のページからの **iframe埋め込みも拒否** します（`X-Frame-Options` と CSP の
  `frame-ancestors`）。埋め込めると、透明にして重ねた上からボタンを押させることができます

とはいえ「自分の書いたコードが自分のマシンで動く」ことは変わりません。
インターネットで拾ったコードをそのまま提出するのは避けてください。

**`content/` に置いたJSONは、実行されるコードです。** 解説に添えたサンプルは
「▶ サンプルを実行」でそのまま動きますし、`content/lib/` の `.java` は提出コードと
一緒にコンパイルされます。実行される側には上の時間・メモリ・出力の制限しかかからず、
ファイルの読み書きやネットワーク接続は普通にできます。誰かからもらった章のJSONを
`content/` に置くのは、そのコードを自分のマシンで動かすのと同じことなので、
中身を読んでから置いてください。
